# 在线心理咨询平台医生服务质量监测 Agent

面向在线心理咨询平台运营方的 B2B 服务质检与风险线索监测系统。平台操作员导入授权的咨询记录后，后端识别初诊/复诊；复诊时检索必要的历史咨询上下文。三个专职 Agent 分别为专业服务评价 Agent（D1/D3）、过程与响应评价 Agent（D2/D5）、共情与关系评价 Agent（D4/D6）。风险监测 Hook 命中时，仅触发共情与关系评价 Agent 的 D6 心理风险应对指标；一个证据核验子 Agent 统一负责原文定位、评分依据核查和指标定义校对。

系统评价医生在会话中可观察到的服务行为，辅助平台扩大质检覆盖、定位问题和追溯依据。系统不对患者作临床诊断，不替代专业人员判断，也不会根据未复核的模型输出自动处罚医生或联系患者。

## Agent 工作流程

```mermaid
flowchart LR
    A[导入授权会话：文本/语音/视频] --> B[多模态预处理：校验、规范化、ASR 转写、脱敏、预检]
    B --> C[初诊/复诊识别]
    C -->|复诊| D[授权检索历史咨询并分区注入]
    C -->|初诊| E[构建当前会话上下文]
    D --> E
    E --> F[风险监测 Hook：命中则路由共情与关系评价 Agent 的 D6]
    F --> G[三个专职 Agent 并行评价]
    G --> H[单一证据核验 Agent：定位原文、核查评分依据、校对指标定义]
    H --> O[应用编排器：检查证据状态与分歧]
    O -->|存在待语义判断的分歧| A[分歧仲裁 Agent]
    O -->|无需仲裁| C[确定性评分汇总]
    A --> O2[应用编排器：校验裁决并控制每指标一次重评]
    H -->|核验不充分| O2
    O2 -->|建议重评且额度可用| R[原评价 Agent 定向复评]
    R --> H
    O2 -->|无需重评、已解决或额度已用| C
    C --> M[人工复核门控]
    M --> S[总结 Agent：画像叙述、总评分说明与改进意见]
    S --> J[报告与案件构造]
    J --> K[操作员复核或归档并留审计记录]
```

评价体系沿用竞赛指标表的 6 个维度、18 项指标分布（D1/D2/D3/D4/D5/D6 分别为 2/2/5/3/4/2 项），全部通过版本化 Skill 包定义。确定性评分汇总器生成 6 维质量画像与总评分（受覆盖率门槛约束）；应用编排器在需要语义判断时调用分歧仲裁 Agent，并控制每项指标最多定向重评一次。整体顺序为“评分汇总 → 人工复核门控 → 总结 Agent”。D6 仅由共情与关系评价 Agent 负责，并由 Hook 条件触发。历史咨询只作为有来源标签的复诊背景，评分证据必须定位到本次会话消息；上下文不足、证据无效或评价与证据核验结论冲突时，系统保留限制并提示人工核查。

## 产品与技术结构

- **使用对象**：单平台工作空间中的一名平台质检操作员，不包含组织成员、角色或租户管理。
- **后端**：Python 3.11+、FastAPI、Pydantic 数据契约、可替换的 LLM Provider 接口和版本化 Skill。
- **前端**：规划为 Vue 3 + TypeScript 管理后台，按总览、质量监测、风险中心、复核工作台、评价任务、指标管理、数据接入和审计日志划分。
- **系统形态**：比赛 MVP 采用 FastAPI 模块化单体；前端通过版本化 HTTP API 与后端交互。

```text
.
├── app/                    # FastAPI、Agent 编排、评价规则与基础设施适配
├── frontend/               # Vue 3 后台前端目录骨架

└── docs/
    ├── architecture/       # Agent 与系统架构设计
    └── product/             # 后台 PRD 与后端功能说明
```

## 本地启动

需要 Python 3.11 或更高版本。

### Windows PowerShell

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
python -m uvicorn app.main:app --reload
```

### macOS / Linux

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
python -m uvicorn app.main:app --reload
```

启动后打开 [http://127.0.0.1:8000/health](http://127.0.0.1:8000/health)，服务应返回：

```json
{"status":"ok"}
```

### 运行测试

```bash
python -m pytest
```

测试覆盖预处理管道的阶段编排与可评价性判定、脱敏失败阻断、评价协调器的超时与失败隔离、证据引用的归一化匹配，以及各注册表的失败语义，共 25 个契约测试。

`/health` 只检查 FastAPI 进程是否响应，不代表数据库、模型服务或完整评价工作流已经连通。前端目录目前仅含架构说明和目录占位文件，还没有独立安装与启动命令。

当前代码骨架已包含：FastAPI 入口与组合根装配、多模态会话数据契约（文本/语音/视频消息、ASR 转写元数据、媒体时间区间）、四阶段预处理管道（规范化 → 转写 → 脱敏 → 预检，含可评价性判定与安全阻断）、带超时与并发预算的多 Agent 协调器、错误隔离的 Hook 注册表、确定性证据核验工具（引文归一化匹配、媒体区间校验）、分歧仲裁 Agent 与总结 Agent 的协议占位、画像/冲突/仲裁/改进意见数据契约、评分汇总器与复核门控接口、内存仓储和 25 个契约测试。尚未实现：真实 LLM Provider 与 AgentRunner、三个正式评价 Agent 的完整执行、证据核验子 Agent、分歧仲裁 Agent 与总结 Agent 的完整执行、评分汇总与门控规则、复诊历史检索、风险监测 Hook 规则、持久化和后台 API。产品文档描述目标闭环，不代表上述模块都已可运行。

## 多模态输入与预处理边界

- 会话消息支持文本、语音、视频三种模态；原始音视频只保存在受控媒体存储中，**不进入模型上下文**。
- 语音/视频消息经 ASR 转写为带引擎版本与时间偏移的派生文本后才可评价；证据引用可附带媒体时间区间，供前端跳转回原始音视频位置。
- 脱敏在评价前强制执行：文本脱敏产生的映射保存在隔离仓储中，仅供审计与人工复核，不进入 Agent 输入或报告；脱敏阶段失败会阻断整条评价链路。
- 转写引擎与脱敏规则集均为可替换适配器；当前分别为"未配置显式报错"和"仅限合成演示数据"的占位实现。

## 数据与安全

- 演示优先使用合成会话；未经授权不要导入真实咨询记录。
- 不要提交 `.env`、患者身份信息、数据库文件、私有对话或本地向量索引。
- 评价结论必须与会话证据分开记录平台规则知识；引用无效或证据不足时不应给出确定分数。
- 复诊历史仅按可信匿名患者标识和平台授权检索；历史片段与本次消息分开标注，不能作为本次医生行为评分的直接证据，并需记录访问审计和执行保留/删除策略。
- 高风险结果是平台内部待核查线索；人工复核和平台处置流程保留最终判断权。

## 工程说明

仓库提供可启动的 FastAPI 服务入口和健康检查，Agent 与评价流程按模块化架构组织。真实模型供应商、持久化数据层和后台页面应在满足平台授权与安全要求后接入；当前的 `/health` 响应不代表完整质检产品已可投入运营。
