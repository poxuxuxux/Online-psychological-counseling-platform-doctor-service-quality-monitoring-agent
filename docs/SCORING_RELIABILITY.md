## 提交与恢复

18 项规则正文统一使用 `status / reason / evidence_ids / claims`，规则所声明的工具改为实际预加载的 `get_dialogue`。默认每次建议提交两项，输出截断或格式错误后缩小为一项；格式错误连续三次后终止，供应商超时/服务错误仍连续两次后终止。单 Agent 累计模型时间默认 300 秒，整个运行仍为 600 秒，环境变量可覆盖。

`submit_evaluation` 按指标返回 `accepted / rejected / remaining_metric_ids`，错误中包含指标编号及结构错误字段。成功项保留，失败项单独修正；完全相同的重复提交不消耗修订预算。尚未修正的拒收项阻止任务完成。没有其他 Agent 在运行时，孤立的 WAITING 任务可在原预算内唤醒一次。

已结束但执行未完成的私有运行可调用 `POST /api/v1/runs/{id}/retry` 创建新 run，再调用返回的 execute 地址。新运行保留已提交结果、冻结规则、严重风险标记及未解决协作线索，补评缺失、拒收和未解决冲突涉及的项目，原报告与审计保留不变。前端数据库会话报告提供补评按钮。访客上传使用临时数据库，不能通过此接口恢复。真实材料缺口或专业复核不通过重试自动消除。

## 结果与总分

报告 schema 2.2 的 `outcome` 区分 `scored`、`not_applicable`、`configuration_blocked`、`execution_failed`、`insufficient_evidence`、`manual_review`、`conflict`，执行失败提供 `failure_code`。页面区分执行失败、专业复核与材料不足，系统补入的空结果不再计为已提交评价。

`quality_profile.policy_version=eligible-metrics-v2` 的报告以同一个后端覆盖门槛控制总分、总览与画像。D2.1/D2.2 的配置排除记录在 `score_exclusions`，不再让全部有效分数被界面隐藏。其他适用但无法评分的指标仍阻断总分。不适用项从分子和分母同时排除，全部指标排除时不生成总分。

`collaboration_complete` 与计分门槛分开：主责评价完成且没有未处理消息、未审查的已报告冲突、未解决冲突或可确定的相反事实主张时，Team Lead 单独执行失败不会抹去综合分。但报告仍标记复核未完成，保留复核原因并在界面说明。显示分数不意味着独立语义核验或团队复核已通过。旧报告继续使用旧门槛，不静默重新解释已有记录。

指标权重仍默认 1，未引入新业务赋权。`observation_complete` 仍默认 false；页面提示完整性未确认，不能自动把记录标为完整。明确可见的行为仍可评分，缺失行为判断继续要求完整观察。

规则正文改变会更新目录版本哈希，新旧规则版本的趋势仍不直接比较。补评沿用旧运行的冻结规则；采用新规则应发起全新评价。

## 验证与发布

后端回归测试覆盖真实 18 项目录、D2 排除、部分提交、错误分类、截断恢复、补评鉴权及未决冲突门控；模型使用可编程替身，不调用真实供应商。

前端源码修改后必须在项目根目录执行 `pnpm --dir frontend build:backend`，完成类型检查、Vite 构建并同步到 `app/web`，FastAPI 托管的网站才会使用新界面。只重启后端不能更新静态文件。本轮未获准下载前端依赖，因此尚未完成完整前端测试、类型检查或构建；已有 `app/web` 静态产物保持原版本，不能把它作为本次源码修复的验证结果。
