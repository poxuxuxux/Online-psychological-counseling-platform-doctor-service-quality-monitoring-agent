# 咨询列表与核查优先级（2026-10-13）

## 已实现的操作

评估工作台上方先显示咨询 ID 列表，每页最多 5 条。支持按 ID 查询、翻页和刷新；点击 ID 后，下方显示对应咨询原文和最新保存的评价报告。读取已有报告只发 GET，不自动重新评价；尚无报告时保持未评价状态。切换 ID 先清空旧记录，校验响应所属 ID，再同时显示原文与报告；快速切换或切换数据来源时丢弃过期响应。

离线预览提供 3 个明确标注的合成咨询，数据保存在内存，不写入服务器。每条咨询有独立消息 ID 和独立报告；总览的独立统计样例仍有明确说明，不冒充这 3 条工作台数据的统计。

## 后端接口

- `GET /api/v1/consultations?limit=5&offset=0&query=`：返回 `database_configured`、`total`、`items`。每条含 `session_id`、`consultation_round`、`message_count`、`updated_at`、可空的 `evaluation_status`。排序按咨询更新时间、ID 降序；未评价的咨询也进入列表。
- `GET /api/v1/consultations/{session_id}`：返回 `{session, report}`，`report` 可为 null。读取该咨询最新报告，按报告时间、评价 ID 降序，使用同一次查询配对记录与报告。
- 查询失败返回 503 和通用提示；记录不存在返回 404。前端不把数据库错误替换成模拟记录。
- 旧后端没有列表接口、数据库未配置或空库时，页面可回退到实际 `/demo/session` 返回的内置合成记录，并明确展示“后端演示记录”。这个回退不代表已读取真实数据库。

当前公开服务没有登录与访问权限模块；新增查询沿用现有公开演示范围，只读取 `source_id = synthetic-demo` 的记录。**真实咨询数据接入应先由后端配置平台身份认证与访问范围，再调整来源过滤，不能直接移除过滤向公网开放原文。** 本次未读取用户的生产数据库，也未更改数据库配置或插入示例数据。后端若采用其他表结构，按上述契约适配存储层即可，前端不需要数据库账号。

## 核查优先级规则 v1

仅对原本待核查的项目进行排列，不修改 Agent 原评价、分数、核验状态或确定性评分门槛。

| 优先级 | 当前处理规则                                       |
| ------ | -------------------------------------------------- |
| 高     | D6 风险响应 / 转介指标，或者材料冲突、明确核验异议 |
| 中     | 证据不足、Agent 执行未完成、适用性或评分锚点不匹配 |
| 低     | 其余常规待核验或规则确认                           |

规则集中于 `frontend/src/utils/reviewPriority.ts`，便于团队后续调整；每项展示分级理由。高、中、低表示审核顺序，**不是患者临床危急程度，也不是模型置信度**。数量卡可筛选，高优先级排在前面，空筛选不会展示或允许处理其他指标。核查范围仍为当前所选咨询，跨咨询的全平台复核队列与正式复核写入接口需要后续接入。

前端构建后的页面资源同步到 `app/web`，供现有 FastAPI / Railway 服务使用。本次更新需要后续提交与部署才能改变线上页面。
