## 1. 产品概述

平台方的质检操作员需要从大量咨询服务记录中发现服务质量问题和需要关注的会话。逐条人工抽查耗时，抽样覆盖有限，复核依据也难以统一。比赛 MVP 假设只有一个平台工作空间和一个质检操作员账号，由同一位操作员完成导入、任务发起和人工复核。

本产品为平台方提供服务质量监测后台：接收经平台授权的咨询记录，由后端评价流程产生带消息证据、置信信息和规则版本的质检结果；后台帮助工作人员筛选风险线索、核查原始证据、作出人工复核决定并追踪处理过程。

系统定位为**运营质检辅助工具**。它不进行患者诊断，不替代专业人员判断，也不应让未经人工复核的模型输出自动导致医生处罚、患者处置或公开排名。

## 2. 产品目标与衡量方式

### 2.1 目标

1. 提高咨询服务记录的质检覆盖率，减少重复的人工初筛工作。
2. 让风险线索可以按优先级进入复核队列，并能快速定位会话证据。
3. 统一质检指标、规则版本和复核留痕，支持结果解释和事后审计。
4. 为平台运营提供任务进度、质量趋势、复核积压和数据覆盖的可见性。

### 2.2 产品指标

- **质检覆盖率**：已完成评价的有效会话数 / 纳入质检范围的有效会话数。
- **复核积压量**：待处理案件数及按风险级别拆分的数量。
- **复核及时率**：在平台配置的处理时限内完成复核的案件占比。
- **证据可追溯率**：质检结论能定位到有效会话消息证据的比例。
- **复核改判率**：人工复核后被确认、驳回或修正的结果分布，用于发现规则或模型偏差。

指标必须展示统计周期、样本量和适用范围。样本不足时显示“样本不足”，不得用小样本生成误导性排名或准确率宣传。

## 3. 用户与权限

| 用户 | 职责 | 权限范围 |
| --- | --- | --- |
| 平台质检操作员（唯一账号） | 导入数据、发起质检、查看风险线索、人工复核和检查审计记录 | 在单一平台工作空间内执行全部 MVP 操作 |

MVP 使用一个由服务端配置的操作员账号，不做组织成员管理、角色配置、邀请、租户切换或案件分派。登录状态仍由后端验证；前端隐藏按钮不能替代服务端校验。查看会话内容、导出数据、修改指标和提交复核决定等操作仍需记录审计事件。未来扩展多平台客户时，再增加租户隔离和多角色权限模型。

## 4. 主要业务流程

1. 平台质检操作员通过授权的数据源或文件导入咨询会话。
2. 服务端校验格式、来源和访问权限，并执行必要的数据脱敏。
3. 操作员选择范围和已发布的指标版本，创建评价任务。
4. 评价流程生成结构化质检结果、风险线索、证据引用、置信信息和规则版本。
5. 证据无效、置信不足或命中需关注规则的结果进入待复核队列；其他结果归档为待抽检或已完成状态。
6. 操作员查看脱敏会话、证据消息和评价依据，提交人工决定及理由。
7. 后台更新案件状态并保留原始 Agent 结论、人工决定、操作者和时间；操作员查看趋势和待处理案件。

## 5. 功能需求

优先级：P0 为比赛 MVP 核心闭环，P1 为后续运营能力，P2 为规模化增强项。

### 5.1 登录与工作空间

- **FR-AUTH-01（P0）**：唯一操作员使用服务端配置的账号登录；未登录时不可访问后台业务页面。
- **FR-AUTH-02（P0）**：服务端验证操作员会话；前端不提供角色或工作空间切换。
- **FR-AUTH-03（P1）**：提供安全退出，退出后清除浏览器中的登录态和业务缓存。

### 5.2 质检总览

- **FR-OV-01（P0）**：展示评价任务总数、运行中/完成/失败数量、待复核案件数和当前复核积压。
- **FR-OV-02（P1）**：按时间范围展示质量维度趋势、案件类型分布、证据可追溯率和复核改判情况。
- **FR-OV-03（P0）**：提供从统计卡片跳转到对应任务或案件筛选结果的入口。
- **FR-OV-04（P0）**：所有统计显示更新时间、时间范围和样本数；无数据、加载失败和样本不足均有明确状态。

### 5.3 会话接入与评价任务

- **FR-IMP-01（P0）**：支持比赛演示所需的合成数据导入；导入记录展示成功数、失败数和失败原因。
- **FR-IMP-02（P1）**：提供 CSV/JSON 批量导入和平台 API 接入配置；上传前展示字段映射及校验结果。
- **FR-EVAL-01（P0）**：操作员可按时间、数据来源和指标版本创建评价任务，并确认任务范围。
- **FR-EVAL-02（P0）**：任务详情展示排队、运行中、完成、失败等状态，支持查看失败原因及已完成进度。
- **FR-EVAL-03（P0）**：每份评价报告记录指标/Skill 版本、运行时间、证据核验状态和可用的置信信息。
- **FR-EVAL-04（P1）**：操作员可取消、重试或导出任务摘要；重试不覆盖旧运行记录。

### 5.4 风险中心

- **FR-RISK-01（P0）**：按风险类别、级别、时间和处理状态筛选案件。
- **FR-RISK-02（P0）**：列表展示案件摘要、风险线索、关联任务、证据状态、创建时间和处理状态。
- **FR-RISK-03（P0）**：支持将案件标记为待处理、处理中或已处理，并保留状态变化记录；MVP 不提供人员分派。
- **FR-RISK-04（P1）**：支持按平台配置的复核时限标示即将超时和已超时案件；时限配置应有业务负责人。
- **FR-RISK-05（P0）**：明确标注风险中心内容为待核实线索；不得把 Agent 风险标签显示为临床诊断或已确认违规事实。

### 5.5 人工复核工作台

- **FR-REV-01（P0）**：展示脱敏后的咨询时间线，并清晰区分咨询者与医生发言、时间戳和消息边界。
- **FR-REV-02（P0）**：从评价结论可跳转到对应证据消息；消息缺失、引用无效或脱敏失败时明确提示。
- **FR-REV-03（P0）**：展示质检维度、Agent 结论、风险规则、证据核验状态和所用规则版本。
- **FR-REV-04（P0）**：操作员可选择确认、驳回、修正、无法判断或升级处理，并填写必需理由。
- **FR-REV-05（P0）**：提交后保留 Agent 原结论及操作员、决定、理由和时间；已提交记录不能静默覆盖。
- **FR-REV-06（P1）**：支持复核历史查看；MVP 不提供队列认领或人员交接。

### 5.6 质检指标与版本

- **FR-RUB-01（P1）**：查看质检维度、定义、适用范围、评分锚点、风险规则及样例说明。
- **FR-RUB-02（P1）**：新指标版本需完成相应的业务或咨询专业审定后发布；发布后不可改写已被任务引用的版本。
- **FR-RUB-03（P1）**：可查看版本差异、审定依据、生效时间和引用该版本的任务。

### 5.7 数据接入与审计

- **FR-INT-01（P1）**：查看数据源连接状态、最近同步时间和最近一次失败原因；敏感凭据只允许服务端加密保存。
- **FR-AUD-01（P0）**：记录登录、会话查看、导出、任务创建、指标发布、案件状态变化和复核提交等关键事件。
- **FR-AUD-02（P1）**：操作员可按时间、事件类型和对象查询审计记录。

## 6. 页面与导航结构

1. 登录页。
2. 工作台总览。
3. 服务质量监测（趋势、维度和覆盖情况）。
4. 风险中心（案件队列和案件详情）。
5. 人工复核工作台（会话证据与决定表单）。
6. 评价任务（任务列表和运行详情）。
7. 质检指标（指标详情、版本和审核状态）。
8. 数据接入（导入记录与数据源配置）。
9. 审计日志。

比赛 MVP 优先交付单账号登录、总览、评价任务列表/详情、风险队列和复核工作台。指标版本、数据源配置和审计日志视开发时间纳入后续迭代；不建立组织成员和角色管理页面。

## 7. 非功能与安全要求

- **隐私保护**：默认使用合成演示数据；真实咨询内容采用最小化采集、展示和导出。按访问授权脱敏，不在浏览器日志或 URL 中放入会话原文及敏感标识。
- **单工作空间边界**：MVP 仅配置一个平台工作空间，不接受客户端传入工作空间 ID 来切换数据范围；未来支持多平台时，再从服务端认证上下文解析租户并覆盖 API、仓储、缓存、后台任务和导出。
- **可解释性**：评价详情可以还原结论关联的消息证据、所用指标版本和人工复核过程；证据不足时展示“不确定/需复核”。
- **安全边界**：模型结论用于质检线索，不作为自动处罚、临床诊断或紧急干预的唯一依据。
- **可靠交互**：关键操作需显示成功/失败反馈；复核提交应防重复提交，并提示不可逆的审计记录。
- **可访问性与兼容性**：桌面后台优先，保证常用分辨率下表格、对话时间线和复核操作可用；关键状态不能仅依赖颜色表达。
- **数据治理**：需由平台确定数据保留、删除、导出和授权策略；没有业务与合规确认前，不固化跨会话记忆和长期保存期限。

## 8. MVP 验收标准

1. 可以使用合成数据完成导入校验并创建一次评价任务。
2. 操作员能在任务页面看到运行状态，并打开包含维度结果、规则版本和证据引用的报告。
3. 命中复核条件的结果能进入风险队列，并可筛选和打开详情。
4. 操作员可以查看对应脱敏消息、提交决定和理由；决定后能看到完整处理记录。
5. 总览的核心统计可跳转到相应的任务/案件列表，空数据和样本不足均有明确展示。
6. 未登录请求由服务端拒绝；关键访问和操作可在审计记录中追踪，页面不提供用户、角色或工作空间切换入口。
7. 演示流程不依赖真实患者信息，也不将未复核 Agent 输出呈现为最终事实。

## 9. MVP 暂不包含

- 患者端预约、支付、消息沟通或医生工作台。
- 临床诊断、治疗建议、危机自动处置和对患者的直接通知。
- 未经人工复核的自动处罚、医生公开排名或对外准确率承诺。
- 多账号、多角色、组织/租户管理、SSO、实时流式监控和微服务拆分。
- 在缺少授权映射和数据治理规则时进行跨会话患者记忆。

## 10. 依赖与待业务确认项

- 比赛 MVP 的实际会话数据格式、授权证明、脱敏字段和可用于演示的数据集。
- 质检维度、评分锚点、风险等级、复核门槛及规则审核负责人。
- 各案件处理时限、升级路径和复核决定的业务含义。
- 单一演示账号的凭据管理方式、部署环境、数据保留期限和导出审批要求。
- 真实 LLM/API 是否接入；接入前需确定数据是否允许发送至所选服务以及失败降级策略。
