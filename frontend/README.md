# 心衡前端工作台

Vue 3 + TypeScript + Vite，可独立开发，也可以构建为现有 FastAPI `/` 页面。当前在 `feat/quality-console` 分支，基于包含 Railway 演示与 PostgreSQL 存储的 `origin/chore/railway-smoke-config`（74cc7ca），而不是尚未合入演示代码的旧 main。

## 直接查看页面

在项目根目录双击 `frontend-preview.html`，可直接打开离线交互预览，不需要安装依赖或启动服务器。页面会默认进入离线模式，所有数据是预设合成样例。要连接真实后端，请使用以下正常开发或 FastAPI 启动方式。重新生成该文件：`pnpm build:preview`。

## 启动

需要 Node.js 22.12+、pnpm 10.28.0。

```powershell
cd frontend
corepack prepare pnpm@10.28.0 --activate
pnpm install --frozen-lockfile
pnpm dev
```

打开 http://127.0.0.1:5173 。默认将 `/api`、`/health`、`/ready` 和 `/docs` 代理到本机 FastAPI（8000 端口）。没有启动后端时，可点击右上角“查看离线样例”。离线样例明确标注为预设合成数据，不运行模型、不写入服务器。

要接线上合成演示服务，复制 `.env.example` 为 `.env.local`，将 `API_PROXY_TARGET` 设为团队 Railway 服务地址。修改后重启开发服务器。浏览器只使用同源相对路径，无需在前端放置模型、数据库密钥，也无需给生产 API 开放任意 CORS 来源。

## 检查与构建

```powershell
pnpm typecheck
pnpm test
pnpm build
pnpm build:backend
```

最后一个命令将构建出的 index.html 和带哈希的 assets 复制到 `../app/web`。先复制资源，再更新 HTML；保留队友旧资源，避免误删。FastAPI 和现有 Dockerfile 继续使用 app/web，无须修改 Railway 启动方式。**本地保存和构建不会更新线上网站**；经团队评审合并到部署分支后，再由既有 Railway 流程部署。

源码在 frontend/src，app/web 是部署产物。修改源码后必须重新运行 build:backend。不要直接编辑带哈希的编译文件。仓库提交 pnpm-lock.yaml，构建产物随本次前端改动交付；node_modules、dist 和本地缓存不提交。

## 可信显示约定

1. 初评分不等于已核验分数。只有明确有效引用、逐事实支持、适用性与锚点均匹配且无未决问题，才显示“核验通过”。未返回核验记录不自动放行。
2. 总分只取后端 quality_profile.overall_score，要求覆盖门槛通过、完整运行、无待复核或未决仲裁，且所有适用项目都通过核验；前端不重新聚合单份报告的指标分；显示总分按 0–5 分乘以 20 换成百分制。
3. 不适用、证据不足、材料冲突和待核验分别展示；空分数显示空值，不显示 0 分。
4. 引用跳转只查本次会话消息。原文可定位不等于语义核验通过。历史消息不能冒充本次证据。
5. 修订必须显式关联 supersedes_finding_id，并属于同一主责 Agent、同一指标、一次修订。原评价保留在详情中。
6. 缺少讨论或仲裁记录时显示“尚未返回”；动画不会假装后端已有实时进度。
7. 线上现有规则使用 D1～D5 维度级演示名称，与正式二级指标不同，页面明确区分。离线样例中的评分和核验意见仅用于交互验收，不代表学术、临床或评分有效性验证。

## 现有接口

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| GET | /api/v1/demo/session | 加载合成会话 |
| POST | /api/v1/evaluations | 发送 ConversationSession，取得 EvaluationReport |
| GET | /api/v1/evaluations/recent?limit=20 | 最近摘要 |
| GET | /api/v1/evaluations/overview?days=30 | 去重后的质量统计，days=1～90 |
| GET | /health | 应用存活 |

最近摘要接口没有旧报告全文，页面不会伪造“打开历史全文”。当前后端只允许 source_id=synthetic-demo 的演示请求；本前端不提供真实数据上传、假登录或假提交复核。

## 后端联调的增量字段

既有 EvaluationReport 字段保持兼容。为展示真实讨论与裁决，前端预留两个**可选**数组，缺省为 []；现有 FastAPI 响应模型需要增加对应字段后才会透传。它们只记录可公开的结构化观点与证据，不要求模型隐含推理过程：

```json
{
  "discussions": [
    {"finding_id":"finding-xxx","role":"verifier","text":"引文可以证明建议发生，尚不能证明建议可执行。","message_ids":["m02"],"timestamp":null}
  ],
  "arbitration_decisions": [
    {"conflict_id":"conflict-xxx","metric_ids":["D5.4"],"status":"unresolved","adopted":"manual_review","rationale":"评分锚点仍无法确认。","requires_manual_review":true}
  ]
}
```

discussion.role 可为 evaluator/verifier/arbiter；裁决 adopted 为 initial/re_evaluated/verification/manual_review。必须与报告中的 finding_id、metric_id 对应。前端没有增加 Agent，也没有在浏览器实现仲裁或评分算法。

## 数据总览与统计规则

导航中的“数据总览”展示四个汇总卡片、六维雷达图、维度平均分表、日均总分折线图、分档比例以及每日数值表。支持最近 7 / 30 / 90 天，手机上图表可以横向滚动查看，数值表保留可访问的数据替代。

- 按 session_id（咨询轮次）去重，每轮只使用最新一次保存的评估；先在全部历史中取最新，再按北京时间的保存日期筛选。重复评估不增加参评对话数。失败重跑不会沿用旧分数。
- 用户确认的百分制规则：总分 ≥ 85 为优质，总分 < 60 为风险。60 分属于中间档，85 分属于优质。这里的风险是服务质量偏低，与患者心理危机风险不同。
- quality_profile 目前的契约是 0–5 分，统计展示只乘以 20；不改变指标权重，也不自行补出后端未生成的总分。分类使用未四舍五入的分数，显示均值才做格式化。
- 已参评但未生成可信总分的报告计入参评与待核验 / 复核数，不进入优质、风险、总均值或折线图。可信条件包括完整执行、明确仲裁状态、无待复核、覆盖门槛通过、正式二级指标、事实核验与评分锚点通过、唯一有效核验记录，以及维度画像与最新指标分关联一致。
- 只聚合最新有效评分版本；其他版本单独计数，不混入均值。目前指标发布版本需在该报告中统一，下一阶段应补充报告级 rubric_version 契约。当前后端的维度级确定性演示结果缺少正式评分画像与语义核验，因此会进入待核验数，图表保持空状态。
- 维度均值以有该维度正式有效分数的对话为分母，显示每维样本数。无数据与不适用不填 0；真实的 0 分仍为有效数值。日均总分按评估日期分组，缺失日期不连线。
- 数据库未配置时计数返回 null，显示“—”；数据库已配置但没有记录时显示 0；请求失败时展示错误，不使用离线数字替代。不会把最近 20 条摘要当成全量统计。
- 合成会话数量单独提示。离线预览的总览是独立预设的汇总布局样例，并非从工作台样例报告计算而来，不写入数据库、不调用模型。

本次新增的只读统计接口由 app/evaluation/analytics.py 和 PostgresEvaluationStore.overview_records 提供；它不增加 Agent、不改写评分、不修改数据库结构，返回聚合值，不返回会话原文或个人标识。必须与前端一起发布到 Railway；线上旧服务未部署该接口时，前端会明确提示缺失。
